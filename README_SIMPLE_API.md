# SimpleAPI: Легковесный конструктор нативных примитивов

**SimpleAPI** — это компактная библиотека-конструктор на языке C++11 под Linux, предоставляющая коллекцию независимых
высокоуровневых примитивов для построения сверхбыстрых, отказоустойчивых и локальных распределённых систем.

Проект разработан со строгим соблюдением стандарта **C++11** для обеспечения максимальной совместимости со старыми
кодовыми базами и имеет **0% внешних зависимостей** (для работы асинхронного сетевого слоя требуется только системная
библиотека `-lpthread`). Это прагматичный архитектурный фундамент для встраиваемых систем, IoT-инфраструктуры и
локальных сред управления чем-либо.

---

### 🏎️ Нативные метрики и легковесность

SimpleAPI гарантирует предсказуемое поведение памяти и минимальный оверхед:
* **Debug-сборка (`libSimpleAPId.so`):** ~10.9 MB (включая DWARF-таблицы отладки).
* **Release-сборка (`libSimpleAPI.so`):** **~1.1 MB** (чистый, концентрированный машинный код).
* (НУЖНО ПРОТЕСТИРОВАТЬ) **Рантайм-потребление ОЗУ:** от 10–15 МБ при базовом запуске до 30–60 МБ под экстремальной
  нагрузкой (парсер монолитных документов объемом более 20 МБ).

#### 📂 1. Слой данных и управления памятью (Data & Memory)
Отвечает за сериализацию, строгую compile-time типизацию и бережное отношение к куче (Heap), предотвращая фрагментацию
памяти:
* **`simpleapi::Config`:** Двунаправленный полиморфный парсер JSON (RFC 8259) и INI со встроенным сквозным сохранением
  многострочных комментариев человека «до» и «после» значений. Файлы не теряют структуру при перезаписи.
* **`Static Config (SAPI_REGISTER_CONFIG)`:** Высокоуровневая декларативная фиксация динамических графов во встроенные
  типы данных и структуры C++ с автоматической лямбда-валидацией параметров. Избавляет от рантайм-аллокаций дерева
  парсера. Добавляет структурам из класса Config автодополнение от IDE.
* **`Variant` & `Visit()`:** Zero-Heap примитивы, обеспечивающие константный полиморфизм типов без выделения памяти на
  куче с использованием *placement new* на фиксированном внутреннем буфере. Можно воспринимать как аналоги
  std::variant<> и std::visit() из более поздних стандартов C++.
* **`simpleapi::Optional<T>`:** Умная compile-time обёртка для опциональных параметров. В случае использования Static
  Config автоматически генерирует пару ключей `<key>` и `<key>_optional` в итоговом текстовом конфиге.

#### 🔍 2. Слой контекстного и синтаксического контроля (Syntax & Context)
Инструменты, обеспечивающие точную обработку текстовых потоков, контроль последовательностей и генерацию отчетов об
ошибках компиляторного уровня:
* **`simpleapi::EECounter` (Сквозной счётчик последовательностей):** Циклический автомат скользящего окна (Sliding
  Window) со встроенным контролем переполнения регистров. Полностью перегружен на уровне операторов C++ для вычисления
  сетевых окон доставки фрагментированных пакетов.
* **`simpleapi::tools::Stacker`:** Сверхлёгкий линейный автомат (O(N)) для контроля вложенности парных скобок (`{}`,
  `[]`, `()`) и строковых литералов, полностью изолирующий контекст разбора от экранированных кавычками текстов.
* **`simpleapi::ParserSymbolCounter`:** Идемпотентный трекер рантайм-координат (строка/символ) во входящем потоке со
  встроенной защитой от сброса при откатах парсера (backtracking), выдающий точное местоположение синтаксического
  брака.
* **`OnlySizetOrString`:** Гетерогенный вариант-контейнер, позволяющий прозрачно перемещаться по смешанным путям
  вложенных массивов и объектов (например, `std::vector<OnlySizetOrString>{"users", 0, "hash"}`).

#### ⚙️ 3. Слой локального сетевого транспорта и утилит (Network & System)
Набор низкоуровневых швейцарских ножей, избавляющих бизнес-логику проекта от платформенной рутины:
* **`simpleapi::SocketThread`:** Асинхронный сетевой UDP-движок, инкапсулирующий логику сокетов ОС в отдельном
  pthread-потоке. Самостоятельно нарезает потоки данных на пакеты и дефрагментирует их на приёмной стороне.
* **`utils::GetAllFilesByMask`:** Рекурсивный сканер файловой системы с поддержкой `regex`-фильтрации путей и
  настраиваемой глубиной прохода (вплоть до бесконечной `-1`).
* **`utils::Timer`:** Потокобезопасный наносекундный таймер-будильник с поддержкой стандартных chrono-литералов и
  возможностью безопасного изменения интервала опроса периферии «на лету».
* **Сетевые HEX-конвертеры (`ToHexString` / `FromHexString`):** Нативные методы быстрого преобразования сырых векторов
  байт `std::vector<uint8_t>` в шестнадцатеричные строковые представления для отладки и логгирования пакетов сокетов.

### 🛠️ Текущий статус сетевого транспорта

В текущей версии библиотеки сетевой слой ориентирован на **строго локальное взаимодействие** в пределах доверенного
периметра LAN:
* **Контроль целостности (CRC):** Расчет контрольной суммы реализован по принципу **простого суммирования байт**
  (аналогично отображению UDP-чексумм в Wireshark) для минимизации CPU-оверхеда на встраиваемых нодах.
* **Гибкий размер пакета:** Пользователь может задать любой размер передаваемого сообщения от 0 до максимального MTU
  (хардкод-значения под специфику старых коммутаторов) через интерфейс конфигурации `SocketSettings::setMaxLength()`.
* **Отсутствие шифрования:** Текущий транспорт передает сырой payload. Защита каналов связи вынесена в планы на
  глобальную переработку сетевой части.

### 🌐 Теоретические сценарии применения (Локальная экосистема Life OS)

Идеи распределенной системы *Life OS* могут быть интегрированы разработчиком исключительно в качестве примеров
локального применения текущего функционала:

#### 1. Сбор локальных метрик умного дома (Smart Home)
По примитиву `utils::Timer` управляющий ПК собирает показатели датчиков внутри домашнего LAN-периметра. Данные
упаковываются в структуру `Static Config` и отправляются UDP-пакетом. Порядковый номер пакета строго контролируется
через скользящее окно `EECounter`, предотвращая дублирование логов на сервере при асимметричных сетевых задержках
коммутатора.

#### 2. Фоновый аудит и синхронизация локальной базы знаний
Связка рекурсивного сканера и полиморфного парсера позволяет организовать быструю проверку локальных каталогов. Вызов
`GetAllFilesByMask("/mnt/nas/notes", R"(.*\.(json|ini)$)", -1)` собирает дерево персональных заметок. Парсер `Config`
на лету считывает структуру файлов, сохраняя пользовательские комментарии «до» и «после» полей. При обнаружении опечаток
`ParserSymbolCounter` фиксирует точные координаты строки и символа сбоя, формируя человекочитаемый отчет в терминале.
