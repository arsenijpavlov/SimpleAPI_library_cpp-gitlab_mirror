# 5. Работа с комментариями

Библиотека SimpleAPI позволяет при работе с файлами конфигураций считывать и записывать пользовательские комментарии.
Комментарии будут стандартизированы по стилю первого вхождения комментария при парсинге файла/строки конфигурации.

Работа с комментариями внутри библиотеки представлена классами `Comment` (хранилище) и `CommentDesign` (настройка
стиля). Оба класса являются вложенной частью сущности `simpleapi::Config` (инициализированы по умолчанию как указатели):
`simpleapi::Config::Comment` и `simpleapi::Config::Comment::CommentDesign` соответственно.

SimpleAPI различает два вида комментариев: комментарий `ДО значения` и комментарий `ПОСЛЕ значения`.

## Комментарий ДО значения (префиксный)
Все описанные комментарии между предыдущим элементом и ключом будут сохранены как один префиксный комментарий к ключу.
Наличие нескольких независимых комментариев порождает их склеивание в один `std::string` добавлением знака переноса
`\n`. Все комментарии до конца чтения значения будут записаны как один префиксный комментарий.
Для ручного заполнения комментария к объекту `Config` следует использовать методы `Config::setPrefixComment()` или
более общий `Config::setComment()`.

## Комментарий ПОСЛЕ значения (суффиксный)
Суффиксный комментарий к значению может быть строго один. Триггером начала отслеживания завершающего комментария
является полностью прочитанное значение. Триггером конца суффиксного комментария считается символьная связка конца
многострочного комментария либо перенос строки, находящийся за пределами текущего комментария.

Ширина колонки многострочного комментария после значения не влияет на вывод. Будет сделана попытка записать такой
комментарий в одну строку, если нет пользовательских переносов строки '\n'.

## Пример написания комментариев внутри файла
```
/* многострочный комментарий
   главного элемента */
// дополнительный однострочный комментарий главного элемента
/* ещё один многострочный комментарий
   главного элемента */
{
  // два однострочных
  // комментария вложенного элемента с ключом "key"
  "key": /* ещё часть префиксного комментария "key" */ "value" /* многострочный комментарий
                 описанный после значения
                 представлен одним сплошным вхождением
                 до переноса строки после описания значения
                 */
  // этот однострочник будет воспринят парсером как префиксный комментарий второго вложенного элемента
} // однострочный комментарий после главного элемента
// данный однострочный комментарий не будет сохранён при чтении файла!
```

## Стиль комментариев. Класс `simpleapi::CommentDesign`
Настройки работы с комментариями являются частью объекта `simpleapi::Config`, но при этом могут быть заданы как
самостоятельный элемент, например, при чтении файла:
```c++
using namespace simpleapi;

CommentDesign cd;
cd.with_comments = true; // включаем сохранение при чтении/записи
cd.oneline_comment_variants.push_back({';', 0}); // добавили правило обрамления комментария 

Config cfg = ParseJson("./my_json_file.json", cd);
```

### Детали реализации:
* стиль написания комментариев определяет параметр `CommentDesign` корневого элемента, если в метод/функцию не передан
  иной объект `CommentDesign`
* пользователь может задать собственные стили однострочных комментариев, дополнив вектор `oneline_comment_variants`
  статическим массивом из двух элементов `char` - правило начала комментария
* для добавления правил многострочных комментариев нужно дополнить вектор `multiline_comment_variants` статическим
  массивом из трёх элементов `char` (более подробно ниже)
* по умолчанию используется стиль комментариев для языка программирования C/C++, то есть `// comment` для однострочных
  комментариев и `/* comment */` для многострочных; будут применены только если не подошло ни одно из пользовательских
  правил для чтения
* при парсинге всегда заполняется `CommentDesign::opt_multiline_column_size` по максимальной ширине колонки
  многострочных комментариев за весь файл

### Однострочные комментарии (пример)
Пример добавления нового шаблона поиска (стиль `bash`):
```c++
CommentDesign cd;
cd.oneline_comment_variants.push_back({'#', 0});
```
Вектор принимает `std::array<char, 2>`. Оба символа являют собой строку, которая обозначает начало однострочного
комментария и действует до переноса строки (кавычки внутри комментария не создают вложенность). Если второй символ
указан как число 0 (без кавычек), то начало комментария определяется строго одним символом.

### Многострочные комментарии (пример)
Пример добавления нового шаблона поиска:
```c++
CommentDesign cd;
cd.multiline_comment_variants.push_back({'{', '|', '}'});
```
Вектор принимает `std::array<char, 3>`. Суть описания похожа на однострочные комментарии за тем исключением, что наличие
третьего символа обозначает замыкающую границу комментария.

Примеры использования:
- `{'{', '|', '}'}` -> `{| multiline comment |}`
- `{'{', 0, '}'}` -> `{ multiline comment }`
- `{'{', '|', 0}` -> `{| multiline comment |{`


## Логика сравнения объектов CommentDesign
Следует держать в уме тот факт, что нельзя однозначно сравнить два CommentDesign с разными opt_multiline_column_size.

Проблема исходит из того, что при попытке записать такой стиль на комментарий, который как самую максимальную строку
принимает, например, N-1 (N - ширина колонки), то следующий парсер, который будет читать из этого результата в своём
результате увидит ширину колонки как N-1.

## Используемые библиотекой обработчики
За запись комментариев отвечает внутренняя функция tools::ToComment().

За парсинг отвечает функция tools::FromComment():
* однострочный комментарий:
    - может обрамляться 1 или 2 символами
    - если второй символ в строке пробел, то в *CommentDesign* запишется первый элемент и 0
* многострочный комментарий:
    - может обрамляться 1 или 2 символами (3 символ указывается как замена 1 при закрытии блока комментариев)
    - правильную границу комментария определяет функция чтения конфига
    - здесь проверка на существование границы в конце будет опускаться



## Важные замечания
### with_comments:
Комментарии не будут прочитаны или записаны, если поле `CommentDesign::with_comments` в составе объекта CommentDesign не
равно true.

### CommentDesign
Переменная объекта CommentDesign в составе Config будет обновлена и дополнена при чтении нового файла/входной строки
конфига.

### Колонка
Для многострочных комментариев можно ограничить ширину колонки. Строки будут обрезаны автоматически. 

Для включения функции следует использовать поле `CommentDesign::opt_multiline_column_size`. 

Значение 0 отключает параметр.

### Рамка
Для многострочных комментариев можно указать стиль рамки, например:
```c++
CommentDesign cd;
cd.opt_multiline_border = '*';
```

Выведет так:
```
/**********
* comment *
**********/
```
Значение 0 отключает параметр.

### Стиль многострочного комментария
Для многострочных комментариев без рамки вывод по умолчанию указывает начало и конец комментария на отдельных строках,
например:
```
/*
multiline
comment
*/
```

Поле `CommentDesign::opt_multiline_border_at_content_line=true` изменяет этот момент:
```
/* multiline
   comment   */
```

### Итоговый вид комментариев в строке вывода
Комментарий можно указать ДО значения и ПОСЛЕ него.

Несколько комментариев ДО значения сформируют один большой комментарий.

Комментарий ПОСЛЕ значения применяется только в том случае, если после написания значения комментарий был начат до
переноса строки. 

Комментарий ПОСЛЕ значения может быть только одним:
```json
{
        // много
        // комментариев
        // ДО значения
        key="value", // комментарий ПОСЛЕ значения
        /* ещё
        один пример */
        /* вторая часть второго примера */
        key2=12465 /* большой
                комментарий
                после значения
                */
}
```

### Уникальная обработка колонки комментария ПОСЛЕ значения
При записи комментария ПОСЛЕ значения параметр `CommentDesign::opt_multiline_column_size` не влияет на ширину колонки,
если в комментарии нет хотя бы одного явного переноса строки (\n). В таком случае будет сделана попытка записать
комментарий как однострочный (для лучшей читабельности итогового конфига).
