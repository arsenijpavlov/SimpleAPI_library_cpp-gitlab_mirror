# 4. Класс `simpleapi::Config`

Библиотека SimpleAPI предоставляет разработчикам прикладных программ удобный, а, главное, не перегруженный интерфейс
в рамках своих инструментов. Базовым классом для работы со структурами настроек/конигураций является класс 
`simpleapi::Config`.

Класс `simpleapi::Config` представляет собой высокоуровневый интерфейс для хранения и управления примитивами значений.
Таковыми на данный момент являются следующие типы: пустой объект (`nullptr`) `ValueType::eNull`, логический тип (`bool`)
`ValueType::eBool`, числа (`long double`) `ValueType::eNumber`, буквы (`char`) `ValueType::eChar`, строковые значения
(`std::string`) `ValueType::eString`, индексные массивы `ValueType::eArray`, и ассоциативные массивы `ValueType::eJson`.
В перспективе будет добавлена поддержка собственных типов для хранения форматов XML и YAML (имеют расширенные правила,
по сравнению с обычным ассоциативным массивом).

Числовые типы сейчас представлены типом `long double`, поэтому стоит учитывать его максимально допустимое хранимое
значение в рамках используемой пользователем операционной системы. Для хранения очень больших чисел предлагается
предварительно упаковывать их в std::string.

Пример работы:
```c++
#include "SimpleAPI.h" // единый заголовочный файл для использования любой из возможностей библиотеки

int main(void) {
    using namespace simpleapi;
    
    CommentDesign cd;
    cd.with_comments = true; // выставляем флаг, если нужно искать комментарии
    Config cfg = ParseJson("/home/user/Downloads/my.json", cd); // аргумент cd опциональный
    if(cfg.containsKey("key")) {
        // если в .toString() не указать аргументы, то значение выведется в компактном виде (не зависит от типа)
        std::cout << "key exists, value: " << cfg["key"] << std::endl;
    } else {
        std::cout << "key not found" << std::endl;
    }

    return cfg.error() ? -1 : 0; // в случае ошибки парсинга будет заполнено поле ошибки
}
```

Конструкторы `simpleapi::Config` позволяют создать объект `Config` на основе любого поддерживаемого классом типа.
Примитивы создаются простой передачей, списки - через указанием первым аргументом требуемого типа. Ассоциативный массив
предполагает указание типа и чередование ключей и значений:
```c++
Config cfg_int_1(100);
Config cfg_int_2(ValueType::eNumber, 100);
Config cfg_string_1("my_string");
Config cfg_string_2(ValueType::eString, "my_string");
Config cfg_bool(true);
Config cfg_bool(nullptr);
Config cfg_arr(ValueType::eArray, 15, "asd", "asd");
Config cfg_json(ValueType::eJson, "key1", 10, "key2", Config(ValueType::eArray, 1, 2, 34.5));
```


**Используйте файл Config.h как источник актуальной информации о доступных методах.**
**Обращайте внимание на отметки API_ в конце объявлений методов.**

## Класс `simpleapi::Config` предоставляет пользователю следующие возможности: 
1) методы работы с комментариями (информацию об их специфике смотрите в соответсвтующем разделе)
2) методы работы с комментариями элементов внутри контейнеров (имя метода пишется через знак подчёркивания '_')
3) методы установки значения - используйте методы `.setValue()` или `operator=()`
4) методы получения значений примитивов: `.getBool()`, `.getNumber()` (есть методы для прямого преобразования чисел к
    нужному формату, например, `.getUInt32_t()`, `.get<T>()`), `.getString()`
5) методы работы с `Config` как контейнером (имя метода пишется через знак подчёркивания '_'), например, `.get_at()`,
    `.get_front()`, `.get_bool_at()` и т.д.
6) методы работы с контейнерами `Config` как набором итераторов: `.getRange()` и `.getMapRange()` для соответствующих
    типов контейнеров - индексные и ассоциативные
7) операторы сравнения одиночных объектов `Config` (опционально проверяются комментарии), а также сравнение контейнеров
    `Config` (опционально задаётся проверка сортировки элементов); опциональные параметры задаются при сравнении через
    метод `.isEqual()`
8) парсинг и запись `JSON` документов и файлов: `.toString()` с указанием формата вывода - 
    `.toString(ConfigFormat::eJSON)`
9) парсинг и запись `INI` документов и файлов: `.toString()` с указанием формата вывода -
    `.toString(ConfigFormat::eINI)`
10) если парсинг завершился с ошибкой, то метод `.error()` вернёт сам факт ошибки, а метод `.getError()` даст строку с
     описанием ошибки; корректно прочитанные поля и значения не будут очищены
11) методы очистки значений `.clear()` и `.clearContainer()` (не удаляет сам контейнер, но очищает его содержимое)
12) методы добавления значений в контейнер: `.insert_*()` и `.push_*()`
13) методы удаления значений из контейнеров: `.erase_*()` и `.pop_*()`
14) методы получения константы значения с последующим удалением из контейнера: `.get_and_pop_*()`
15) методы получения информации о параметрах объекта: `.getType()`, `.is*()`, `.isEqual()` и т.п.
16) методы получения количества элементов внутри `Config`: контейнеры дадут актуальное количество элементов внутри,
     `eNull` всегда даст 0, другие типы - 1
17) методы определения наличия ключа или значения внутри контейнера: `.containsKey()` и `.containsValue()`
18) операторы присвоения (аналог `.setValue()`)
19) методы и функции работы с файлами для чтения и записи конфигов


## Некоторые интересные факты о работе класса
Разрешено использовать ключи без наполнения - "".

Форматы `INI` и `JSON` свободно конвертируются один в другой. Из-за особенностей реализации формата INI бывают случаи,
когда двойная конвертация даст другое расположение ключей (при записи в JSON создаются пустые ключи "", которые
используются для хранения вложенных элементов).

Если объект `Config` является контейнером, то используя метод `.append()` можно добавить к нему элементы из другого
контейнера того же типа.

Если ключа в `Config` ещё не существует, то он обращение к нему создаёт такой ключ и заполняет его `ValueType::eNull`.

Объект `Config` с типом `eNull` при использовании контейнерных методов группы добавлениия (`.insert*()`/`.push*`())
самостоятельно преобразуется в указанный тип кконтейнера перед добавлением в него значения, переданного пользователем.

Класс `Config` не генрирует исключения (по понятным причинам это правило не касается `std::bad_alloc`).
Любая ошибка работы класса меняет флаг `.error()` на `true` и заполняет `.getError()` строковым описанием ошибки.

Ошибка парсинга не затирает корректно прочитанные поля и значения, но при этом наличие ошибки всё ещё можно отследить
методами, указанными выше.

Ввиду особенностей хранения больших дробных чисел, часть вводимой информации может оказаться избыточной. В конечном
итоге в переменную числа запишется только некоторая часть дроби - знаки после фактически значимой части дроби пропадут
уже при повторном чтении конфига. Например, число в текстовом конфиге `-0.400000000000000022204` будет корректно
прочитано как `-0.4`.
_(Пока нет отлаженного алгоритма, который бы позволил без потерь срезать избыточную информацию дроби)_
