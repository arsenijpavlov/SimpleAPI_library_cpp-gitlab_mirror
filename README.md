- `SimpleAPI`         — содержит исходный код библиотеки.

# 1. Архитектурная философия и стандарты

## Стандарт C++11
Полная автономность кодовой базы без требований к современным стандартам (C++14/17/20/23).

## Максимальная обратная совместимость (Legacy)
Железобетонная работоспособность на старых кросс-компиляторах (проверено на GCC 4.9.4) и старых версиях системных библиотек (glibc 2.14.4) под архитектуры ARM (сборка phyFLEX под специализированную плату для задач телекома).

## Zero-Dependency (Self-Contained)
Библиотека зависит только от `pthread` (для класса `SocketThread`). Никаких внешних тяжёлых зависимостей вроде `Boost`, `nlohmann/json` или `protobuf`. Весь ключевой функционал написан с нуля.

## Философия открытых примитивов
Библиотека предоставляет высокоуровневые интерфейсы, но оставляет открытыми для разработчика все низкоуровневые примитивы, полезные в обычных проектах и embedded-разработке (скрыты в более глубоких пространствах имён).

## Краткое описание пространств имён
- `simpleapi::`      — корневые прикладные классы (основной интерфейс разработчика)
- `simpleapi::utils` — прикладные системные утилиты
- `simpleapi::logs`  — прикладные утилиты системы создания логов
- `simpleapi::meta`  — инструменты времени компиляции (метапрограммирование)
- `simpleapi::tools` — скрытые технические классы реализации (например, индексный контейнер `ElementArray`) и интерфейсы.

# 2. Динамическая подсистема конфигурации (класс Config)
Основной интерфейс для гибкой работы с древовидными структурами данных «на лету» (динамический контейнер).

## Управление типами (ValueType)
Поддерживает примитивы (`long double`, `bool`, `std::string`, `const char*`), пустые типы (`ValueType::eNull`, `nullptr`) и структурированные контейнеры (`ValueType::eJson`, `ValueType::eArray`).

## Бесшовная конвертация форматов
Полная рантайм-совместимость и свободная двусторонняя конвертация между JSON и INI внутри одного объекта Config (метод `toString()`), запланировано добавление в эту парадигму поддержку стандартов XML и YAML.

## Отказоустойчивый (Толерантный) парсинг
При возникновении синтаксической ошибки в файле, успешно прочитанные до этого момента ветки данных не уничтожаются. Метод `error()` сигнализирует о сбое, а `getError()` возвращает точную строку описания ошибки.

-----
## Специфика реализации JSON (RFC 8259)

## Поблажки парсера строк
Допускается отсутствие запятых (перенос строки эквивалентен разделителю). Кавычки для ключей/значений обязательны только в случае, если строка содержит несколько слов.

## Отсутствие принудительной сортировки
Данные сохраняют естественный порядок, автоматическая сортировка ключей отсутствует.

-----
## Специфика реализации INI:

## Автовыведение типов
Расширяет стандартный INI. Текстовые значения автоматически распознаются внутренним парсером и приводятся к примитивам Config: числа, строки, bool (true/false, +/-), массивы, вложенный JSON и пустые значения. Строковые значения оборачивать в кавычки можно, но не требуется.

## Поддержка многострочности
Значение переменной корректно считывается на последующих строках, если не закрыта кавычка, строка оканчивается на '\' или следующая строка начинается с пробела/табуляции.

### Склеивание дубликатов в массивы:
Одинаковые ключи в рамках одной группы автоматически преобразуются в массив (`ValueType::eArray`).

### Иерархия через слэш:
Поддерживается глубокая вложенность ключей с использованием разделителей '/' и '\'. При записи JSON-объекты первого уровня становятся секциями, а более глубокие — составными путями.

# 3. Уникальная подсистема сохранения комментариев (CommentDesign)
Round-trip сохранение структуры файлов конфигурации при программной перезаписи, учитывающее пользовательские комментарии.

## Префиксные комментарии
Блоки текста ДО значения. Несколько одиночных строк комментариев подряд склеиваются в один многострочный блок. Задаются методами `setPrefixComment()` и `setComment()`.

## Суффиксные комментарии
Компактный текст ПОСЛЕ значения (от конца значения до переноса строки). При записи библиотека автоматически пытается уместить суффикс в одну строку для сохранения читаемости, несмотря на флаг ширины колонки.

## Кастомизация маркеров
Возможность через `std::array` задать любые пользовательские символы начала однострочных (например, `std::array[char, 2]{'#', 0}` для `# My oneline comment`) и многострочных (например, `std::array[char, 3]{'{', '|', '}'}` для `{| My multiline comment |}`) комментариев. До нескольких форматов за один прогон парсера.
Несмотря на то, что стандарт XML предусматривает 4 символа для начала (`<!--`) и 3 для конца (`-->`) комментариев, библиотека не предоставляет пользователю такой возможности. Любое правило парсинга будет преобразовано в стандартный для XML формат.

## Автоформатирование колонок и рамок
Ограничение максимальной ширины строки многострочного комментария (`opt_multiline_column_size`) с автопереносом строк и возможность отрисовки декоративных рамок (например, `opt_multiline_border = '*'`).

# 4. Статическая конфигурация (концепция Static Config на базе XY-Macro)
Декларативное описание структур через препроцессор (паттерн XY-Macro) для обеспечения строгой типизации и автокомплита в IDE.

## Поддержка типов STL
Полная совместимость со всеми основными контейнерами (`std::vector`, `std::list`, `std::set`, `std::map`, `std::unordered_map`, `std::deque` и так далее).

## Поля simpleapi::Optional<T>
При сериализации автоматически порождают в файле две связанные переменные — значение `<key>` и флаг присутствия `<key>_optional`.

## Поля simpleapi::Variant<T>
Позволяют использовать кастомный выбор единицы хранения для одного имени поля. Задумывались как способ сохранения и чтения SEQUENCE-структур из ASN.1.

## Автогенерация Enum (макрос SAPI_REGISTER_ENUM)
Создает строго типизированный `enum class`, защищённый от дубликатов. Автоматически генерирует сопутствующие функции, принимающие на вход объект описанного `enum class`: `ToString()`, `FromString()` (с фолбеком в состояние `_UNDEFINED_STATE_` при ошибке парсинга строки) и `EnumPossibleVariants()` для вывода всех доступных опций.

## Автогенерация структур (макрос SAPI_REGISTER_CONFIG)
Генерирует методы `bool loadConfig(const Config&)` для каскадного заполнения полей и `Config saveConfig()` для сериализации из статики в динамику.

## Поля Y
Технические поля, которые объявляются внутри макроса структуры, но не участвуют в автоматической работе с динамическим конфигом.

## Декларативная лямбда-валидация (один аргумент)
Позволяет зашивать анонимные функции валидации (`const type& val -> bool`) прямо в макрос объявления поля. При сбое валидации заполняется глобальная строка `static_config_error_str`. Также есть возможность указать лямбду с двумя аргументами, где первым аргументом будет передано прочитанное значение, а вторым аргрументом - имя поля.

## Декларативная лямбда-валидация (два аргумента)
Интроспекция имени поля. Поддерживаются двухпараметрические лямбды вида `[](const T& val, const std::string& key_name) -> bool`, где второй параметр при вызове автоматически заполняется именем текущего поля, позволяя логировать ошибки более лаконичным описанием кода.

# 5. Собственные высокоуровневые примитивы памяти (Аналоги STL)
Созданы для обеспечения полной автономности в рамках стандарта C++11 без раздувания бинарника внешними runtime-зависимостями. Не конфликтуют с STL, но STL-реализации в рамках Static Config использовать не получится.

## Класс simpleapi::Optional<T>
Легковесный контейнер (флаг + значение). Метод `unset()` сбрасывает статус валидности без принудительного удаления/вызова деструктора внутреннего объекта, оптимизируя повторные аллокации и давая возможность считывать старое неактуальное значение.

## Класс simpleapi::Variant<Types...>
Типобезопасный tagged union на вариативных шаблонах (аналог `std::variant<T...>`):
- Вычисляет размер (`size`) и выравнивание (`align_size`) на этапе компиляции через `alignas`
- Выделяет плоский массив байт `uint8_t m_data[size]` во избежание фрагментации памяти кучи
- Управление временем жизни объектов через ручной вызов _placement new_ и явные деструкторы
- Защищён статической проверкой `simpleapi::meta::is_contains_duplicate` от дублирования типов в пакете `<Types...>`
- Быстрый доступ через `.get<T>()` на базе _reinterpret_cast_ (для скорости) и безопасный доступ через `.get_if<T>()` (возвращает указатель или `nullptr`).

## simpleapi::Visit(variant, lambdas...)
Полноценный аналог паттерн-матчинга `std::visit()`:
- Порядок описания функций/лямбд не зависит от порядка подтипов в `Variant`
- Список лямбд может содержать дублирующие включения — это не ломает компиляцию, сопоставление происходит под каждый уникальный подтип

## 6. Низкоуровневая подсистема утилит (simpleapi::utils)
Открытый набор системных кирпичиков, доступных прикладным разработчикам. Большую часть все, так или иначе, пишут заново в каждом своём проекте.

## Честный UTF-8 подсчет
Функция `GetStringCharCount()` вычисляет количество символов в UTF-8 строке по байтовым маркерам стандарта, умеет аппаратно игнорировать невидимые ANSI/VT100 escape-последовательности управления цветом консоли (\033[...]m) и спецсимволы переноса строк.

## HEX-конвертеры
Высокопроизводительные побитовые преобразователи `ToHexString()` и `FromHexString()` / `FromHexStringToHex()` для работы с бинарными дампами без сторонних зависимостей.

## Продвинутый сплиттинг текста
Функции `SplitString()` и `SplitToColumns()` - умное разбиение строки на подстроки заданной ширины с сохранением пользовательских переносов и защитой неделимых слов/многоточий.

## Рекурсивный поиск в ФС (GetAllFilesByMask)
Нативный кросс-платформенный обход директорий на базе POSIX API (<dirent.h>) с фильтрацией файлов по регулярным выражениям `std::regex` и строгим контролем максимальной глубины вложенности (`max_level`).

## Строковые валидаторы типов
Функции `IsStringOfFloatNumber()`, `IsStringOfIntNumber()` и `IsStringOfUIntNumber()` на базе регулярных выражений для безопасного парсинга чисел разного формата из текста.

## Специализированные компоненты
- Рантайм-трекер координат парсера `ParserSymbolCounter`.
- Гетерогенный контейнер `OnlySizetOrString` для навигации по вложенным структурам.
- Сквозной счётчик `EECounter` с двумя уровнями инкрементации (`m_pos` и `m_global_pos`).
- Линейный автомат `Stacker` для контроля вложенности скобок и строковых литералов. Также умеет определять, находится ли текущая позиция внутри одинарных или двойных кавычек.
- Неблокирующий (интервальный) программный таймер `Timer`. Работает на основе меток времени `std::chrono`.

## Журналирование (LoggerSettings и simpleapi::logs)
Легковесный вспомогательный инструментарий для внешних логгеров. Не является самостоятельным логгером. Позволяет управлять метаданными вывода (флаги времени, выравнивания заголовков колонок) и предоставляет функции для быстрой ANSI-раскраски логов (`to_color_string()`, `columned()`).

## Валидация целостности (CRC)
Набор встроенных утилит проверки контрольных сумм CheckCrc8, CheckCrc16 и CheckCrc32 для анализа массивов данных побитовыми сдвигами. Данный набор сейчас имеет самую простую реализацию из возможных и не рекомендуется к использованию вкупе с зашумленными каналами связи.
Будет пересмотрен при проектировании сетевого модуля, устойчивого к глобальным сетям.

# 7. Движок статической инспекции и метапрограммирования (simpleapi::meta)
Продвинутый инструментарий времени компиляции (Type Traits), обеспечивающий строгую работу ядра библиотеки.

## Интроспекция контрактов классов (is_config_struct<T>)
Проверка наличия у типа `T` метода `loadConfig()` на базе SFINAE.

## STL-классификаторы типов
Специализированные классы-детекторы контрактов контейнеров: `is_container_as_vector`, `is_container_as_set`, `is_container_as_unordered_set`, `is_container_as_queue`, `is_container_as_priority_queue`, `is_container_as_stack`, `is_container_as_array`, `is_container_as_bitset`, `is_container_as_map`, `is_container_as_unordered_map`, `is_container_as_variant` (соответствие `simpleapi::Variant`), `is_pair`, `is_optional` (соответствие `simpleapi::Optional`).

## Универсальный диспетчер валидаторов (ExecuteValidator)
Шаблонный механизм, умеющий на этапе компиляции подстраиваться под лямбды разной вложенности аргументов (принимающие только `T`, принимающие `T + key_name`, или пустые `nullptr`). Проверяет возможность вызова лямбд.

## Compile-time калькуляторы Typelist:
Шаблоны рекурсивного вычисления максимального размера (`max_size_of_type`) и максимальной границы выравнивания памяти (`max_align_of_type`) для набора разнородных типов данных (`<Types...>`).

## Индексные итераторы списков типов
Трейты получения типа по индексу (`type_at_index`), поиска индекса по типу через `std::is_same` / `std::is_convertible` / `std::is_constructible` и сложный кросс-индексный маппер списков типов (`for_list<...>::from_list<...>::get::index`).

## Дешифратор Callable-объектов (lambda_settings)
Уникальный для C++11 механизм извлечения типов аргументов (`arg_type`) и возвращаемых значений (`ret_type`) из переданных лямбд, указателей на лямбды и свободных функций через специализацию указателей на методы класса.

# 8. Сетевая подсистема (SimpleAPI Network)
Высокопроизводительный асинхронный/синхронный стек работы с датаграммами по протоколу UDP, компенсирующий ненадежность транспорта собственным протоколом общения `SimpleAPI v1` и событийно-ориентированной моделью.
_Ошибки проектирования протокола будут учтены в рамках следующих версий._

## POSIX UDP-примитивы
Низкоуровневые обёртки над системными сокетами Linux (класс `UDPSocket`), предоставляющие методы ручного управления (`sendRawMsg()`, `recvRawMsg()`) через плоские пакеты `Packet` (aka `std::vector<uint8_t>`).

## Сетевая адресация (IpPort)
Удобная структурная единица под пару IP-адрес + порт, поддерживающая автоматический парсинг строки формата `X.X.X.X:port`.

## Многоканальный асинхронный поток (SocketThread)
- Выносит обслуживание сетевого взаимодействия в изолированный поток ОС (используется `pthread`).
- Реализует концепцию мультиплексирования: метод `addSocket()` позволяет одному потоку обслуживать несколько экземпляров сокетов одновременно.

## Встроенный Reliability Layer (Протокол SimpleAPI v1)
Автоматическая фрагментация и дефрагментация. Деление больших сообщений (включая JSON) на фрагменты заданной длины (`setMaxLength()`) и прозрачная сборка на стороне получателя.
Контроль сессии. Автоматическая проверка активности соединения (обмен пингами раз в несколько секунд) с отслеживанием таймаутов (`setInactivityTimer()`) последней активности адресата.
- Целостность данных. Рантайм-вычисление и сверка контрольных сумм для всего собранного сообщения на базе побитовых CRC-утилит (уровни выкл / 8B / 16B / 32B через `setCrcLevel()`). _Полезность данного примитива под вопросом, зеркальные ошибки битов приведут к валидному результату при невалидном пакете._

## Событийные функции обратного вызова (Callbacks)
- `setNewConnectionCallback()` / `setConnectionResetCallback()` — уведомления о жизненном цикле соединений.
- `setRecvPacketCallback()` — получение от адресата сырого бинарного пакета данных (`PacketMessage`).
- `setRecvJsonCallback()` — автоматический парсинг пришедшего пакета в формат JSON и вызов колбэка с готовым динамическим объектом `JsonMessage` (интеграция с `Config`).
- Логирующие колбэки: `setLogCallback()` и `setLogErrorCallback()` (а также их color-версии для ANSI-графики) для асинхронной маршрутизации строк диагностики напрямую из сетевого потока в логгер приложения.
